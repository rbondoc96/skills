# UI/UX

Own user journeys, navigation, interaction feedback, information hierarchy, and loading/error/empty/success states. Accessibility owns assistive access; code structure owns component implementation.

## Investigate

- Walk the changed task from the user's starting point through completion, recovery, and cancellation. Check whether actions and consequences are understandable.
- Inspect hierarchy, density, responsive layout, copy, validation, and feedback where the change affects decisions or task completion.
- Use an available authorized local browser/session or provided screenshots when useful. Respect project rules about starting servers and accessing live systems.

## Evidence bar

State what was inspected: source, screenshot, or exercised interaction, with relevant viewport/state. Show the user action, obstacle, and effect. Code alone cannot establish rendered usability; record unavailable visual/interaction checks as limitations. Recommend a focused adjustment without editing components or producing an unsolicited redesign.
