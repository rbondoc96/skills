# T3 adapter

Use T3's advertised native collaboration tools directly: `spawn_agent`, `followup_task`, `send_message`, `wait_agent`, and `interrupt_agent`. Do not invoke them through shell or JavaScript orchestration.

## Route

Before dispatching, inspect the current advertised agent models, reasoning overrides, and available slots. Pass model and effort explicitly only when the selected values are advertised; inherited settings must be intentional and recorded in the route. Do not freeze transient slot counts or model names here.

Give each agent the approved dispatch card. Use `followup_task` for a new turn, `send_message` for a queued note, `wait_agent` for completion, and `interrupt_agent` only to stop work deliberately.

## Isolation

T3 agents share the filesystem. Run parallel writers only in separate worktrees. Parallel read-only agents may share the repository. The host orchestrator inspects diffs, integrates results, verifies changes, and accepts or rejects output.

T3 browser behavior is outside this adapter.
